# 철도 IPS 기반 4D/5D — 설계 기준 문서

> 목표: 국가철도공단 IPS(통합공정표, P6) 체계 위에서 **AI 개략공정 → P6 왕복 → BIM 객체·수량·내역
> 자동 연결 → 4D/5D 시뮬레이션**. 1차 마감: 철도 스마트·BIM·AI 기술포럼 서면심사 자료(2026-10-29),
> 발표·시연(2026-11-11). 브랜치 `feature/rail-4d5d-ips`(3차 뷰어 브랜치 `feature/3d-streaming-stability`에서 분기).

## 1. 왜 (문제 정의)
P6 로 IPS 를 만들고 Navisworks 로 4D 를 표현하는 지금 방식의 병목은 도구 기능이 아니라 **연결 작업이
수작업**이라는 점이다. 공정이 바뀔 때마다 객체 연결을 다시 해야 해서 4D 가 1회성 시뮬레이션 영상에
머물고, 수량·금액은 모델과 따로 논다. (Navisworks TimeLiner·SYNCHRO 도 규칙 연결·5D 를 지원하므로
"기존 도구로 불가능"이라고 주장하지 않는다.)

**새로움 = 공단 IPS 구성 표준안을 기준으로 연결 키를 AI 가 자동으로 만들고, P6 수정 왕복 뒤에도
객체·수량·내역 연결을 자동으로 유지하는 것.**

## 2. 흐름
```
① 사업 자료(보고서·도면) + IFC 모델 + 수량산출서 ──AI──▶ IPS 개략공정(표준안 템플릿 + 근거 칼럼)
② 개략공정 ──XER(CP949/UTF-8)──▶ P6 에서 수정·보완 ──XER──▶ 플랫폼 재업로드(버전 비교)
③ 액티비티 ↔ BIM 객체 연결(연결 키 → 규칙, 남는 것만 AI)
④ 객체별 3D 수량(기준) + 수량산출서 대사 → 오차 보고서
⑤ 내역 항목 ↔ 객체 매칭(AI) + 금액 계산(코드) → 객체별 공사비(계약 기준 / 모델 기준)
⑥ 4D/5D: 3차 뷰어 객체 색칠·숨김(setPaint/setStates) + 객체 속성에 공정·공사비 표시
```

## 3. 확정 원칙
1. **P6 는 대체하지 않는다.** XER 읽기·쓰기로 왕복. 공단 표준이 P6.
2. **연결 키는 P6 안에 싣는다.** 구조물·부위 = Activity Code, STA 시작/끝·MIR키 = UDF. P6 에서 작업을
   복사해 쪼개도 코드·UDF 가 따라가므로 재업로드 시 키로 재연결한다. 작업 ID(task_code)만으로 잇지 않는다.
3. **공기는 LLM 이 정하지 않는다.** 일수 = 수량 ÷ 생산성(품셈/실적), 선후관계 = 표준안·구조물 유형 규칙.
   AI 는 템플릿 선택·구조물 목록 추출·누락 검토만. 모든 액티비티에 **근거**(수량·생산성·출처)를 남긴다.
4. **금액 계산은 코드가 한다.** AI 는 "어느 내역 항목이 어느 객체에 해당하는가" 매칭까지. 연결은 다대다 +
   배분율(객체 1 ↔ 레미콘·타설·거푸집·철근, 내역 1 ↔ 객체 여러 개를 수량 비율로).
5. **금액은 두 가지를 함께 둔다.** 계약 기준(내역 금액을 객체에 배분, 합계 = 계약금액, 기성·S-curve 기준) /
   모델 기준(3D 수량 × 단가). 차이 = 오차 보고서의 금액판.
6. **3D 수량 기준은 형상이 있는 항목에만.** 내역 항목 분류: A 형상 직접(콘크리트 체적·강재·말뚝 본수) /
   B 형상 파생(거푸집 = 접촉 면적) / C 모델 없음(산출서 수량 + 객체 배분: 철근·동바리·비계·운반) /
   D 간접비(배분 안 함 또는 공정 단위). 오차 보고서는 A·B 만.
7. **원본 모델은 고치지 않는다.** 연결은 DB 에 두고(객체 키 기준), 필요하면 속성을 넣은 IFC 를 내보낸다
   (Navisworks 규칙 연결과 공존). 모델 새 버전에는 규칙(WBS × 구조물 × 부위 × STA)으로 자동 재적용.
8. **3D 표시는 3차 뷰어**(D24). 객체 키는 SVF dbId — IFC GlobalId 와 잇는 다리 필요(아래 6절).

## 4. 범위(1차)

  ③ 수량 대사 보고서 ④ 4D 화면 + 객체 공사비 ⑤ 수작업 대비 연결 소요시간.

### XER 쓰기 세부
- 템플릿(P6 에서 내보낸 XER)을 주면 그 파일의 **열 구성(+기본 열)·달력·통화·OBS·머리줄**을 따른다 →
  사용하는 P6 버전과 회사 달력에 맞음. 없으면 P6 19~23 기본 열 + 7일·8시간 달력.
- 날짜는 CPM(7일 달력)으로 매김. P6 에서 F9 하면 프로젝트 달력으로 다시 계산된다.
- Activity Code 는 프로젝트 범위(AS_Project), UDF 는 작업 표(숫자 값만 있으면 FT_FLOAT_2_DECIMALS).
- **미검증: 실제 P6 불러오기.** 샘플 XER 을 P6 체험판에서 불러와 확인해야 한다(인코딩 CP949/UTF-8 중
  무엇이 맞는지 포함).

## 6. 화면 구성 — 메뉴 「공정·공사비 (4D/5D)」 (`/project/:id/4d5d`, D29)
3차 뷰어 화면(`ThreeDTest2 variant="svf" sim`)에 하단 도크를 붙인 형태. 레퍼런스: SYNCHRO 4D(3D + 하단 간트),
Navisworks TimeLiner(하단 도크 탭), RIB iTWO 5D(내역 그리드 ↔ 모델).
```
┌ 상단 도구줄: [공정표 열기] [XER 내려받기] 공정표 이름 ✕ | 모델 열기·전체 맞춤·… (3차 뷰어 도구 그대로)
├ 3D(3차 엔진): 연결 객체를 기준일 상태로 칠함(진행=초록·늦음=빨강·빠름=파랑, 미시공=숨김/회색)
│               좌: 모델 트리 · 우: 속성 (기존 패널 그대로)
├ 재생 줄(접어도 남음): ⏮ ▶ ⏭ 속도 ──기준일 슬라이더── 날짜 D+n | 4D 표시 · 미시공 숨김
├ 탭 줄: 공정표 · 차트 · 5D 내역 · 물량 · 연결 현황 ······ 계획 공정률·진행/완료·누적 공사비 | 크게 · 접기
└ 탭 내용(윗변 끌어 높이 조절)
   공정표   왼쪽 표(Activity ID·작업명·일수·시작·종료·연결·공사비, WBS 묶음) + 오른쪽 간트(일/주/월 눈금,
            완료·진행·예정 색, 주공정 빨간 테두리, 기준일 세로선, 눈금 클릭 = 기준일)
   차트     S-curve(계획 공정률 + 누적 공사비), 기준일 세로선, 클릭 = 기준일
   5D 내역  엑셀형 표(공종 묶음·소계·합계, 품명·규격·단위·수량·단가·금액·수량 분류·연결 객체·연결 작업), 엑셀 내보내기
   물량     3D 수량 ↔ 산출서 수량·차이·오차(±3% 초과 빨강)·연결 키, 엑셀 내보내기
   연결 현황 작업↔객체·내역↔객체 연결률
```
- **기준일 하나**를 재생 줄·간트·차트·3D·지표가 함께 본다. 작업 행을 누르면 그 객체가 3D 에서 선택되고, 3D 에서 고른 객체는
  그 객체가 걸린 작업을 선택한다.
- 엑셀형 표(`components/sim45d/DataGrid.tsx`)는 보이는 행만 그려 내역서 수천 줄도 가볍다. 머리줄·합계줄·앞 열 고정.
- 마지막으로 연 공정표는 이 브라우저에 보관(편의용). 서버 저장은 0040 스키마에서.

## 7. 열린 질문
- 주실 IFC 의 객체와 3차 뷰어(통합모델 nwd → SVF) dbId 를 무엇으로 잇나: 속성 패널의 ID 항목
  (Element ID·GUID·IfcGUID) 확인 → 없으면 객체 상자(위치) 대응.
- IPS 구성 표준안의 WBS·Activity 코드 체계(전역 코드인지 프로젝트 코드인지) → 연결 키 이름을 표준안에 맞춤.
- 외부 AI API 로 보고서·도면·내역서를 보내도 되는지(발주처 확인). 발표 자료에서 단가 마스킹.
