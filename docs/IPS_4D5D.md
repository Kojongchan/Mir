# 철도 IPS 기반 4D/5D — 설계 기준 문서

> 목표: 국가철도공단 IPS(통합공정표, P6) 체계 위에서 **AI 개략공정 → P6 왕복 → BIM 객체·수량·내역
> 자동 연결 → 4D/5D 시뮬레이션**. 1차 마감: 철도 스마트·BIM·AI 기술포럼 서면심사 자료(2026-10-29),
> 발표·시연(2026-11-11). 브랜치 `feature/rail-4d5d-ips`(3차 뷰어 브랜치 `feature/3d-streaming-stability`에서 분기).

## 1. 왜 (문제 정의)
P6 로 IPS 를 만들고 Navisworks 로 4D 를 표현하는 지금 방식의 병목은 도구 기능이 아니라 **연결 작업이
수작업**이라는 점이다. 공정이 바뀔 때마다 객체 연결을 다시 해야 해서 4D 가 1회성 시뮬레이션 영상에
머물고, 수량·금액은 모델과 따로 논다. (Navisworks TimeLiner·SYNCHRO 도 규칙 연결·5D 를 지원하므로
"기존 도구로 불가능"이라고 주장하지 않는다.)

**새로움 = 공단 IPS 구성 표준안을 기준으로 연결 키를 AI 가 자동으로 만들고, P6 수정 왕복 뒤에도
객체·수량·내역 연결을 자동으로 유지하는 것.**

## 2. 흐름 — 메뉴 안 단계형 진행(D30, 2026-10-23 사용자 정리)
실제 업무 순서 그대로: 공정표가 먼저 있어야 BIM 에 공정 속성을 넣는다.
```
1 대상 선택      프로젝트·구조물(예: 연제교 상선/하선)
2 자료 준비      단계별 필요 자료 안내 → 자료관리(ACC)에서 고르기 | 그 자리에서 업로드(폴더 선택·새 폴더)
                 보고서(과업개요·시공계획·교량설계) · 수량산출서 · 내역서 · BIM 모델(ACC 변환본)
3 설계현황       구조물·개소(A1, P1…, 경간)·공종·수량을 추출해 표로 보여줌 → 사용자 확인
4 AI 개략 IPS    공단 IPS 구성 표준(준비·조사/하부공/상부공, 30~60일 단위) 템플릿 + 근거 칼럼
                 일수 = 수량 ÷ 생산성(코드), 선후관계 = 표준 규칙 → 검토·수정 → XER 내려받기
5 P6 보완        P6 에서 고친 XER(또는 P6 엑셀 내보내기) 다시 올림 → 버전 비교 → 확정 IPS
6 BIM 연결       확정 IPS 의 Activity ID 를 객체에 부여(규칙 → 남는 것 AI) + 체적 자동 산정 → 검토
7 모델 반영      객체별 속성(IPS 코드·일자) 반영 파일 내보내기(방식은 9절 열린 질문)
8 4D/5D          3차 뷰어 + 하단 도크(공정표·차트·5D 내역·물량·연결 현황)
9 검증 보고서    코드 오기·기간 밖 날짜·실적 누락·수량 대사(±3%)
```
- BIM 속성은 **AI 초안이 아니라 P6 에서 확정된 IPS** 로 부여한다(초안 단계의 ID 는 P6 에서 바뀔 수 있음).
- 현장 모델에 이미 있는 사람 입력 속성(연제교 1,736객체)과 실제 IPS(연제교 324작업)는 4·6단계의 정답셋.

## 3. 확정 원칙
1. **P6 는 대체하지 않는다.** XER 읽기·쓰기로 왕복. 공단 표준이 P6.
2. **연결 키는 IPS Activity ID**(D28 10-23 수정). 확정 IPS 의 Activity ID 를 BIM 객체 속성 `A3_WBS CODE (IPS)` 에
   부여한다. 공단 IPS 에 Activity Code·UDF 를 새로 넣지 않는다(실제 IPS 에 없음). 작업 복사·분할로 ID 가 바뀌면
   재업로드 비교에서 WBS 부모 + 이름으로 다시 잇는다.
3. **공기는 LLM 이 정하지 않는다.** 일수 = 수량 ÷ 생산성(품셈/실적), 선후관계 = 표준안·구조물 유형 규칙.
   AI 는 템플릿 선택·구조물 목록 추출·누락 검토만. 모든 액티비티에 **근거**(수량·생산성·출처)를 남긴다.
4. **금액 계산은 코드가 한다.** AI 는 "어느 내역 항목이 어느 객체에 해당하는가" 매칭까지. 연결은 다대다 +
   배분율(객체 1 ↔ 레미콘·타설·거푸집·철근, 내역 1 ↔ 객체 여러 개를 수량 비율로).
5. **금액은 두 가지를 함께 둔다.** 계약 기준(내역 금액을 객체에 배분, 합계 = 계약금액, 기성·S-curve 기준) /
   모델 기준(3D 수량 × 단가). 차이 = 오차 보고서의 금액판.
6. **3D 수량 기준은 형상이 있는 항목에만.** 내역 항목 분류: A 형상 직접(콘크리트 체적·강재·말뚝 본수) /
   B 형상 파생(거푸집 = 접촉 면적) / C 모델 없음(산출서 수량 + 객체 배분: 철근·동바리·비계·운반) /
   D 간접비(배분 안 함 또는 공정 단위). 오차 보고서는 A·B 만.
7. **원본 모델은 플랫폼이 직접 고치지 않는다.** 연결은 DB 에 두고(객체 키 기준), 모델에 넣을 속성은 반영 파일로
   내보낸다(2절 7단계, Navisworks 규칙 연결과 공존). 모델 새 버전에는 규칙(WBS × 구조물 × 부위 × STA)으로 자동 재적용.
8. **3D 표시는 3차 뷰어**(D24). 객체 키는 SVF dbId, 속성 API 와는 externalId(Revit UniqueId)로 잇는다(9절).

## 4. 범위(1차)
- **교량 1기 관통**(~10/26) → 터널은 모델이 굴진·라이닝 구간 단위로 나뉘어 있을 때만 추가. 토공·가시설 제외.
- 서면심사 자료에 넣을 실측 증거: ① AI 생성 공정표가 P6 에서 열린 화면 ② 정답셋 대비 연결 정확도
  ③ 수량 대사 보고서 ④ 4D 화면 + 객체 공사비 ⑤ 수작업 대비 연결 소요시간.

### XER 쓰기 세부
- 템플릿(P6 에서 내보낸 XER)을 주면 그 파일의 **열 구성(+기본 열)·달력·통화·OBS·머리줄**을 따른다 →
  사용하는 P6 버전과 회사 달력에 맞음. 없으면 P6 19~23 기본 열 + 7일·8시간 달력.
- 날짜는 CPM(7일 달력)으로 매김. P6 에서 F9 하면 프로젝트 달력으로 다시 계산된다.
- Activity Code 는 프로젝트 범위(AS_Project), UDF 는 작업 표(숫자 값만 있으면 FT_FLOAT_2_DECIMALS). 쓰기 기능은 남겨 두되
  공단 IPS 연결 키로는 쓰지 않는다(D28 수정).
- 템플릿에 같은 라벨의 작업 UDF 가 있으면 그 정의(ID·자료형)를 그대로 쓴다(실제 IPS: 계약금액 = FT_MONEY).
- 실제 IPS XER 은 **CP949**(P6 23.0 내보내기). 읽기·쓰기 왕복은 실파일로 확인(8절). **미검증: 우리가 만든 XER 을 P6 에서 불러오기.**

## 6. 화면 구성 — 메뉴 「공정·공사비 (4D/5D)」 (`/project/:id/4d5d`, D29·D30)
맨 위 **단계 바**(대상 칩 + 1~9 단계, 완료 ✓·준비 중 점선)를 누르면 3D 위에 **단계 시트**가 펼쳐지고, 8 「4D/5D」 또는
「3D 보기」를 누르면 접힌다(3D 는 계속 열려 있어 다시 불러오지 않음). 자료 칸마다 [자료관리에서 선택] / [지금 업로드]
(같은 ACC 창: 폴더 열기·＋ 새 폴더·⬆ 이 폴더에 업로드 → 올린 파일이 바로 그 칸에). 지금 단계·대상은 이 브라우저에 기억,
고른 자료는 대상별로 DB 에(팀 공유).

단계 시트 내용(10-23, `components/sim45d/steps/*`). 「AI」 버튼은 결과를 바로 쓰지 않고 표·칩으로 보여 준 뒤 사람이 받아들인다.
- **3 설계현황**: 개소 목록("A1, P1~P46, A2")으로 표를 만들고 말뚝 종류·본수·교각 높이·경간을 고친다. [AI 채우기] = 수량산출서 쪽(범위 지정)에서 추출, 쪽 인용.

## 9. 체적 자동 산정 시험 — 연제교 상선 BR01 (2026-10-23)

- 채택안으로 BIM 연결을 해 보니 하부(기초·교각·코핑·교대 235객체)는 규칙으로 붙고, **상부 497객체(거더·받침·상판)는 경간을 알 수 없어**
  후보 10개로 남는다 — 객체 이름에 경간 정보가 없고, 채택안은 거치를 경간 묶음 작업으로 나누기 때문. 형상(파생 형상의 위치)으로 경간을 정하는 규칙이 다음 과제.
