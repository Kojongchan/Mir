# 4D 시공 시뮬레이션 (S4 · Phase 2)

뷰어 위에 올린 4D 시공 시뮬레이션 1차 기능. 공정 일정(작업: 이름·시작·종료)과
IFC 객체(expressID)를 매핑하고, 타임슬라이더로 현재 시점까지 시공된 객체만 보이게
뷰어 표시를 제어한다.

## 데이터 흐름
```
CSV(Navisworks/Fuzor)
  → schedule.ts (decode + parse)        ScheduleTask[]  (이름·유형·start·end)
  → fourd.ts   (mapByName/mapSequential) TaskMapping     (taskId → [{modelID,expressID}])
  → fourd.ts   (computeStates@now)        Map<el, built|active|future>
  → IfcViewer.applyConstruction(...)      뷰어 표시 제어(숨김/반투명/강조)
```

## 핵심 파일
- `src/lib/schedule.ts` — CSV 파서. **헤더 기반**이라 Navisworks(한글, EUC-KR)와
  Fuzor(영문, UTF-8, ISO 날짜)를 한 파서로 처리. `OutlineNumber` 상위 작업 제외.
- `src/lib/fourd.ts` — 매핑(이름/순서) + 시점별 상태 계산. 한 요소가 여러 작업에
  속하면 `built > active > future` 우선순위. 미매핑 요소는 건드리지 않음(항상 표시).
- `src/viewer/IfcViewer.ts` — `getElementCatalog()`(이름 인덱스),
  `applyConstruction(states, futureMode)`, `clearConstruction()`. 기존
  `setElementVisible` 와 동일한 메시 관리 위에서 동작(공유 재질, 매 틱 복원→재적용).
- `src/components/Timeline.tsx` — 하단 패널: 임포트·4D토글·매핑·재생·슬라이더·간트.
- `src/store/useStore.ts` — `fourd` 슬라이스(일정/현재시점/매핑/모드).

## 매핑 전략 (1차)
1. **이름 매핑(`mapByName`)** — 작업 이름과 IFC 요소 Name 을 정규화해 매칭.
   `"A1 버림: A1 버림"` 처럼 `이름: 별칭` 형태는 양쪽 토큰을 후보로 사용.
2. **순서 자동배정(`mapSequential`)** — 모델 요소를 일정 순서대로 균등 분배. 이름이
   맞지 않는 모델/공정표 조합에서도 시각적으로 동작하는 빠른 데모용(생성 작업에만
   분배, 철거·장비·임시 제외). 이름 매칭이 5% 미만이면 자동으로 이 모드로 폴백.
3. **수동 매핑(UI)** — 뷰어에서 객체를 클릭해 선택한 뒤, 간트 각 작업 행의 `＋`
   버튼으로 그 객체를 작업에 연결. 행의 숫자는 매핑된 객체 수이며 클릭 시 비운다.

## 작업 유형 & 표시 규칙 (Navisworks TimeLiner 모양 모델)
한 요소에 걸린 작업을 시작 시각 순으로 적용해 시점별 표시를 정한다(시공 후 철거 등).
유형별로 시작 전/진행 중/완료 후 모양이 다르다.

| 유형 | 시작 전 | 진행 중 | 완료 후 | 의미 |
|---|---|---|---|---|
| **Construct(시공)** | 숨김(미시공) | 초록 반투명 | 정상(모형) | 공사 중인 것 |
| **Demolish(철거)** | **정상(기시공 상태로 존재)** | 빨강 반투명 | 숨김 | 기시공된 것을 철거(예: 가시설) |
| **Temporary(임시)** | 숨김 | 노랑 반투명 | 숨김 | 임시 구조물(예: 공사용 가도, 임시가설교량) |

- "진행 중" 반투명 불투명도 기본 **50%**(슬라이더 조절), 색상은 유형별로 변경 가능
  (시공=초록/철거=빨강/임시=노랑 기본, 색상 선택기). 표시 설정은 `표시 ▾` 버튼.
- "미시공" 요소는 기본 숨김, **미시공 반투명(ghost)** 체크 시 흐릿하게 표시.
- 상태/외형 계산은 `src/lib/fourd.ts`(`CellState`), 렌더 적용은
  `IfcViewer.applyConstruction(states, AppearanceSettings)`.

## CSV 가져오기 (열 매핑)
임포트 시 `src/components/ColumnMapModal.tsx` 가 떠서 **어떤 CSV 열을 어떤 속성
(이름·작업유형·계획 시작/끝·실제 시작/끝·비용·동기화 ID·개요번호)에 매핑할지** 선택한다.
자동 추정값(`readCsv().guess`)이 채워져 있어 보통 그대로 확인만 하면 된다(Navisworks
필드 선택기 유사). 확정 후 `buildSchedule(doc, columnMap)` 으로 작업을 생성한다.
역할에 안 쓰인 열은 작업의 `custom`(사용자 값)으로 보존되어 테이블에 표시할 수 있다.

## 작업 테이블 (헤더/열)
하단 패널은 헤더가 있는 표 + 간트로 구성: **공정명·유형·상태·계획 시작·계획 끝·맵핑·간트**
(기본). `상세 열` 버튼으로 **실제 시작·실제 끝·비용**을 추가 표시. 현재 시점은 간트에
세로 커서로 표시되고, 막대는 유형색 + 상태(예정 흐림/진행 강조/완료) 로 칠해진다.

## 성능
`applyConstruction` 은 메시별로 마지막 적용 외형을 기억해, 재생 중 **상태가 바뀐
메시만** 갱신한다(대형 모델이 매 틱 전체를 다시 칠하지 않음).

## 영속화 (DB 저장/로드)
- 스키마: `supabase/migrations/0003_schedule.sql` — `schedules` / `schedule_tasks` /
  `task_elements`(다대다) + `models` 와 동일한 RLS(`is_member`/`is_admin`). 추가형·멱등.
- 데이터층: `src/lib/scheduleApi.ts` — `listSchedules` / `saveSchedule` /
  `loadSchedule` / `deleteSchedule`. 작업/요소 id 는 클라이언트 생성 UUID 로 매핑
  상관관계를 정확히 보존. `task_elements` 는 `(db model_id, express_id)` 로 저장.
- UI: 하단 타임라인의 **DB 저장 / 불러오기 / 삭제**(저장 일정 select). 프로젝트 멤버만.
- **런타임 변환**: web-ifc 런타임 `modelID` 는 로드마다 달라지므로, 불러올 때
  `(db model_id, expressID)` 를 **현재 활성 모델의 런타임 modelID** 로 변환한다(현재
  단일 활성 모델 가정; 다른 모델 매핑은 해당 모델을 열어야 적용).
- 📌 라이브 검증은 `0003` 적용 + 배포/`vercel dev` 환경에서(원격 세션 egress 제약).
  미적용 시 저장/목록은 에러로 안내되며 CSV 임포트·로컬 시뮬레이션은 그대로 동작.

## 알려진 한계 / 다음 단계
- ✅ (반영) **철거(demolish) 의미**: 철거/임시 작업 완료 시 객체를 숨김(removed).
- ✅ (반영) **수동 매핑 UI**: 간트 행 `＋` 로 선택 객체를 작업에 연결.
- ✅ (반영) **증분 갱신**: 상태가 바뀐 메시만 갱신.
- ✅ (반영) **DB 저장/로드**: 0003 스키마 + `scheduleApi.ts` + 타임라인 UI. 라이브
  검증은 마이그레이션 적용 후 배포 환경에서(원격 세션 egress 제약).
- (보류) 정밀 GUID 매핑(동기화 ID/Fuzor GUID ↔ 요소): 샘플 ID 체계가 제각각이라
  우리 기준을 먼저 정립한 뒤 보완하기로(현 단계 미추가). 파서는 externalId 를 보존.

## 인코딩 메모
샘플 CSV 는 **UTF-8 BOM** 으로 저장되어 한글 Windows Excel 에서도 안 깨진다. 임포터는
UTF-8/EUC-KR(CP949) 를 자동 감지하므로, 사용자가 Excel(CP949) 또는 UTF-8 로 만든 한글
공정표 모두 그대로 임포트된다(BOM 은 디코딩 시 제거).
